# 柑橘 · 知乎（astrbot_plugin_citrus）

让机器人在用户问「知乎热榜有什么」「这个问题大家怎么看」「评论区在争论什么」的时候，
**真的去知乎抓内容**，再交给模型总结 —— 而不是让它凭记忆编。

底层是 [citrus](https://github.com/)（统一社交平台读接口，只读、零第三方依赖）。
本插件把 citrus 直接以库的形式打包进来，所以**不需要额外起服务、不需要 pip 安装任何东西**。

---

## 它提供什么

### 1. 模型自动调用（function calling）

向模型注册了四个工具，用户正常提问就会自动触发：

| 工具 | 什么时候用 | 参数 |
|---|---|---|
| zhihu_hot | 知乎热榜、今天在讨论什么 | limit |
| zhihu_search | 找某个话题下的问题/回答/文章 | query、limit |
| zhihu_read | 读一个问题或回答的正文（问题会带高赞回答） | ref、with_answers |
| zhihu_comments | 评论区怎么看、有哪些不同意见 | ref、limit、sort |

另外会在用户消息提到「知乎」时，往系统提示词里补一句「去调工具，不要凭记忆编」，
提高命中率（可在配置里关掉）。

### 2. 确定性指令（不依赖模型判断）

```
/知乎热榜 [条数]
/知乎搜 <关键词>
/知乎看 <链接或内容ID>
/知乎评论 <链接或内容ID> [条数]
/知乎状态
/知乎帮助
```

指令结果默认再让模型总结成一段话（配置里可关）；关掉后直接返回抓到的列表，更快更省 token。

## 安装

### 方式 A：WebUI 上传（推荐）

1. 把 astrbot_plugin_citrus.zip 传到 AstrBot WebUI 的「插件」页（上传插件 / 从文件安装）；
2. 安装完成后在插件列表里把它启用。

### 方式 B：docker cp

```bash
docker cp astrbot_plugin_citrus <容器名>:/AstrBot/data/plugins/
# 然后在 WebUI 插件页点「重载插件」，或重启容器
```

插件目录结构必须长这样（目录名不能改）：

```
/AstrBot/data/plugins/astrbot_plugin_citrus/
  main.py
  bridge.py
  render.py
  metadata.yaml
  _conf_schema.json
  vendor/citrus/...
```

## 配置 Cookie（最关键的一步）

1. 电脑浏览器里**登录知乎**；
2. 按 F12 打开开发者工具 → **Network** 面板；
3. 随便点一条发往 www.zhihu.com 的请求；
4. 右键 → **Copy** → **Copy as cURL**；
5. 回到 AstrBot →「插件」→ 找到本插件 → 配置 → 把整段粘进 **知乎 Cookie** 输入框 → 保存。

四种格式都认：**cURL 整段**、请求头块、裸 Cookie 串、{"z_c0": "..."} 这种 JSON。
粘贴内容里的 z_c0 是登录态，没有它多半会报「未登录」。

> 也可以用「Cookie 文件」那项：把 cURL 存成文件（比如挂载进容器），在配置里填路径即可，
> 适合换号频繁或不想把 Cookie 存进 AstrBot 配置文件的人。

保存后发一句 /知乎状态，能看到 Cookie 指纹（**不会显示原文**）和上游连通性。

## 白名单

默认只允许名单里的用户使用（私聊、群聊都按发送者 ID 判断）：

1. 让用户在自己的会话里发 /sid（AstrBot 自带指令），拿到 ID；
2. 把 ID 填进插件配置的「允许使用的用户 ID」列表。

名单为空 = 谁都不能用（会回一句「你不在知乎插件允许的用户名单里，你的 ID 是 xxx」，
把 xxx 填进去就行）。想对所有人开放，把「谁能用」改成 all。

## 配置项

| 配置 | 默认 | 说明 |
|---|---|---|
| 知乎 / 启用 | 开 | 关掉后所有知乎能力不可用 |
| 知乎 / Cookie | 空 | 粘贴 cURL |
| 知乎 / Cookie 文件 | 空 | 上面为空时读这个文件 |
| 默认平台 | zhihu | 以后接更多平台时用 |
| 谁能用 | whitelist | whitelist / all |
| 允许使用的用户 ID | 空 | 白名单 |
| 提到知乎时提醒模型调工具 | 开 | 提升自动调用命中率 |
| 指令结果再让模型总结 | 开 | 关掉=直接返回原始列表 |
| 总结用的系统提示词 | 空 | 留空用内置；可写语气偏好 |
| 热榜默认条数 | 10 | 1-30（知乎热榜不给翻页） |
| 搜索默认条数 | 8 | 1-20 |
| 评论默认条数 | 30 | 1-100 |
| 单条正文字数上限 | 1500 | 200-16000，防止撑爆上下文 |
| 单条评论字数上限 | 200 | 40-800 |
| 列表摘要字数上限 | 120 | 20-600 |
| 读问题时附带几条高赞回答 | 3 | 0-5 |
| 附带回答的字数上限 | 600 | 100-3000 |
| 请求最小间隔(ms) | 350 | 别长期设 0，那是给自己找风控 |
| 请求随机抖动(ms) | 250 | 让请求节奏更像人 |
| 单次上游请求超时(ms) | 20000 | |

## 常见错误怎么办

/知乎状态 会直接告诉你是哪一环不通。对照表：

| 现象 | 原因 | 处理 |
|---|---|---|
| 还没有配置知乎 Cookie | 配置里 Cookie 为空 | 按上面步骤粘贴 cURL |
| Cookie 里的登录态失效了 | z_c0 过期 | 重新登录知乎，重新复制一次 |
| 被知乎风控拦住了（弹了验证页） | 触发反爬验证 | 去浏览器过一下验证，等几分钟；**不要连续重试** |
| 知乎限流了 | 请求太密 | 等几分钟；把间隔调大 |
| 本机网络请求失败 | 容器出不去网 | 检查容器网络/代理 |
| 模型不调用工具 | 模型/提供商没开工具调用 | 在提供商配置里允许工具调用；或直接用指令 |

## 它是怎么工作的

```
用户消息
   │
   ├─ /知乎热榜 ─────────────┐
   └─ 普通提问 → 模型 → 调工具 ┘
                              ▼
                     main.py（参数校验、白名单、渲染）
                              ▼
                  bridge.py（asyncio.to_thread + 串行锁）
                              ▼
              vendor/citrus（Cookie 解析、限速、缓存、错误翻译）
                              ▼
                        www.zhihu.com
```

几个刻意的设计：

* **citrus 是同步的**，插件用 asyncio.to_thread 把它挪出事件循环，再用一把
  asyncio.Lock 串行化 —— 和知乎「一次只发一个请求」的礼貌节奏一致；
* **错误统一翻译**：no_credential / not_logged_in / challenge / rate_limited
  都变成人话 + 下一步动作，交给模型转述给用户；
* **只读**：不点赞、不评论、不关注、不私信。citrus 里根本没有写接口；
* **不绕过风控**：没有验证码破解、没有代理池、没有随机换 IP。撞上验证页就如实报错。

## 隐私

* Cookie 只存在 AstrBot 的插件配置文件（或你指定的文件）里，以及进程内存里；
* 日志里只有**指纹**（#8562c066 这种），永远不打印原文；
* 工具输出里不含 Cookie，测试里有一条专门检查这个；
* 数据目录：/AstrBot/data/plugin_data/astrbot_plugin_citrus/（citrus 的缓存与临时状态）。

## 开发与测试

插件目录下：

```bash
# 离线测试：起一个假知乎，跑通所有工具和指令（20 个用例）
python -m unittest discover -s tests -t . -v

# 真实链路冒烟：用本机 ~/.citrus 里已有的 Cookie 打一次真知乎（只发一个请求）
python tests/live_check.py
```

测试里用 tests/harness.py 给 AstrBot 打了桩，所以不需要真的装一个 AstrBot。
